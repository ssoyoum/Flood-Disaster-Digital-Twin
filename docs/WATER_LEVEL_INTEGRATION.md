# water-level-rise → FloodOps 연결

확인일: 2026-10-10. 현재 연결 범위는 **실제 관측의 모델 입력 구성과 연구 검증 근거**다. 학습된 모델의 실제 시설 추론·통제 판단 적용은 미완료다.

## 가져온 것

- 옆 저장소 `water-level-rise/baseline.py`의 기본 입력 22종 계약.
- LightGBM·XGBoost·CatBoost 혼합 모델의 구성과 원본 OOF(학습 데이터의 교차검증 예측) 오차. 원본 CSV를 다시 계산해 확인했다.
- 실제 미호강교 수위에서 기준 시점 및 1·3·6·12·24시간 전 입력 6종을 만드는 어댑터. 가능한 수위 변화량·가속도도 산출한다.
- `#twin` 보드의 24시간 이력 카드와 별도 예측 연결 상태 API.

학습 CSV·제출 예측 CSV·모델 파일을 FloodOps에 복사하지 않았다. 원본 프로젝트를 수정하거나 실행하지 않고, 특징 목록은 Python AST로 읽었다. 기존 백엔드에 세 모델의 학습 라이브러리를 추가하지 않았다.

## 원본 자료를 실제 관측처럼 붙일 수 없는 이유

사용자가 보유한 `02_참가자공개.zip`의 `README_PARTICIPANT.md`와 `data_dictionary.csv`, 저장소의 학습·개발 문서를 확인했다.

- 관측소는 `ST0001` 같은 익명 ID다. 실제 WAMIS·홍수통제소 관측소 코드와 연결표가 없다.
- 시각은 합성 시각이다. 같은 사건 안의 시간 간격은 유지하지만 실제 날짜·계절·절대시각을 뜻하지 않는다.
- 참가자 가이드는 공개 WAMIS 자료와 대조해 익명 관측소·원래 시각을 복원하는 것을 금지한다. 그런 대조는 수행하지 않았다.
- 원본 수위는 해발고도(EL)와 관측소 기준 수위가 혼재하므로 관측소 간 절대값을 직접 비교할 수 없다.
- 모델의 학습 특징은 파생변수를 포함해 43종이다. 익명 관측소별 통계 특징도 있어 기본 입력 22종을 채우는 것만으로 새 관측소 추론이 검증되는 것은 아니다.

이 문서의 참가자 조건은 원본 데이터의 사용 가능성을 판단하는 근거다. 사용자의 이번 요청 범위는 FloodOps 연결이다.

## 예측 목표와 확인한 성능

목표는 `max(WL(t+1h), …, WL(t+6h)) − WL(t)`이며 단위는 m다. 다음 여섯 개 시간대의 최대 상승량이고 음수도 유효하다. 지하차도 침수심이나 임계 도달 시각을 직접 예측하는 목표가 아니다.

| 검증 근거 | 확인값 |
| --- | ---: |
| 원본 학습 OOF 행 | 749,657 |
| 전체 OOF RMSE | 0.2215642409 m |
| 정답 상승량 > 1 m인 OOF 행 | 18,889 |
| 위 구간 RMSE | 1.0998626389 m |
| 원본 제출 예측 행 | 186,263 |
| FloodOps 실제 시설 예측 점수 | 미검증 |

이는 원본 학습 데이터의 내부 교차검증이다. 숨겨진 테스트 정답에 대한 점수·FloodOps 실측 성능·실제 재난 대응 효과를 뜻하지 않는다. 급상승 구간 오차가 더 커서 전체 평균만으로 대응 성능을 주장할 수 없다.

## 현재 입력 연결

| 입력 묶음 | 종수 | 현재 상태 |
| --- | ---: | --- |
| `wl_t`, `wl_t_minus_{1,3,6,12,24}h` | 6 | 등록 시설의 실제 수위 이력으로 구성; 관측 없으면 `null` |
| IMERG 누적 강우 1·6·24h | 3 | 미연결; 유역 대표성과 누적 방식 확인 필요 |
| 지상 격자 강우 1·6·24h | 3 | 미연결; 단일 AWS 값과 동등하다고 가정하지 않음 |
| 레이더 평균·p95·임계 이상 비율 | 3 | 미연결; 원본 변수의 단위·집계 정의 확인 필요 |
| 집수면적·유역면적·평균고도·평균경사·도시/산림비율·하천차수 | 7 | 미연결; 시설과 관측소를 대표하는 유역 및 원본 단위 확인 필요 |

궁평2지하차도 2023-07-15 08:00 재생에서는 기본 22종 중 수위 6종이 확보된다. 나머지 16종을 0이나 가까운 관측소의 다른 변수로 채우지 않는다.

수위 입력은 요청 시각 이하의 가장 최근 관측을 기준으로 만든다. 미래·다른 관측소·비유한 값은 제외하고, 과거 입력은 정확한 시간차의 관측만 허용한다. 보간·직전 값 복사·0 채우기는 하지 않는다. 같은 시각의 수위가 충돌하면 오류로 반환한다. `wl_observed_range_24h`는 여섯 입력의 범위이며 24시간 전체 시계열의 최대·최소 범위가 아니다.

10분 관측은 20분, 1시간 관측은 90분까지 신선한 것으로 분류한다. 최신 관측의 지연과 24시간 전 입력을 함께 확보하려고 요청 시각 이전 26시간을 조회한다. 누락·지연은 상태와 차단 사유에 표시한다. 실시간 수집 오류를 2023년 관측으로 대체하지 않는다.

## 사용 방법

화면: 소개 화면의 **지하차도 통제 판단 보드** → 아래쪽 **24시간 수위 이력**. 사건 시각을 바꾸면 이력도 같은 시각으로 갱신된다. 펼침 항목에 입력 연결 수·내부 검증 오차·실측 검증 대기가 표시된다.

```text
#twin?at=2023-07-15T08%3A00%3A00

GET /api/twin/facilities/gungpyeong2-underpass/forecast-readiness
GET /api/twin/facilities/gungpyeong2-underpass/forecast-readiness?at=2023-07-15T08:00:00
```

`at`이 있으면 설정과 무관하게 과거 재생으로 읽는다. 없으면 기존 `FLOODOPS_TWIN_MODE`·홍수통제소 키 설정을 따른다. 시간대 없는 시각은 KST이며 `Z`·UTC 오프셋은 KST로 변환한다.

응답의 `features`·`derived_features`·`history`에는 실제 관측 입력을, `missing_features`·`blockers`에는 추가 필요 조건을, `research`에는 원본 연구 검증 근거를 담는다. 다음 값은 실제 시설 추론 검증 전까지 고정한다.

```json
{
  "status": "RESEARCH_ONLY",
  "prediction_available": false,
  "prediction_maxrise_6h_m": null,
  "control_decision_usable": false
}
```

미등록 시설은 404, 잘못된 시각은 422, 수집·계약 읽기 오류는 503이다. 오류 메시지에 원본 URL의 키나 내부 경로를 넣지 않는다. 이 요청의 실패는 기존 보드의 관측·판정·백테스트 표시와 분리했다.

## 연구 근거 갱신

```powershell
python data/scripts/import_water_level_research.py --project ../water-level-rise
```

기본 입력 개수·유한 OOF 값·전체/급상승 오차·학습/제출 행 수를 확인한 뒤 `data/manifests/water-level-research.json`을 만든다. 검증 오차는 원본 JSON과 절대 허용차 `1e-10`으로 대조하며, 소스·평가 파일 SHA-256을 남긴다. API가 계약을 캐시하므로 갱신 후 백엔드를 재시작한다.

## 실제 예측으로 확장할 순서

1. 실명 관측소와 실제 시각을 가진 별도의 수위·강우·레이더·유역 데이터를 확보하고 단위·집계·기준면·시설 대표성을 확인한다. 익명 자료의 재식별을 전제로 삼지 않는다.
2. 실제 관측소에 맞춰 학습·전처리 계약을 구성한다. 익명 관측소별 통계는 그대로 이식하지 않고 재학습하거나 제거 후 재검증한다.
3. 실제 사건별 시간 분리 검증으로 미래 누출을 막고, 단순 지속·선형 상승 기준과 비교한다. 급상승 구간의 오차·과소예측·추론 지연도 따로 평가한다.
4. 먼저 연구 예측과 관측을 함께 기록해 검증한다. 6시간 최대 상승량으로 임계 도달 분을 만들지 않으며, 필요한 경우 별도의 시간대별 예측 목표와 검증을 추가한다.
5. 현장 계측·시설별 유입 경로·관리기관 규칙을 대조한 뒤 통제 검토 보조 지표의 적용 범위를 결정한다.
