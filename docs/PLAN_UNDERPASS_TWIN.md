# FloodOps 새 기획안 — 지하차도 통제 판단 트윈

작성일: 2026-10-14 · 방향 결정: 2026-10-10 · 근거: [TODO.md DIRECTION](../TODO.md), [WORKLOG.md](../WORKLOG.md)

## 1. 한 문장으로

> **"이 지하차도, 지금 막아야 할까?"** 에 답하는 화면.
> 하천 수위를 실시간으로 받아 지하차도가 **지금 몇 단계인지**, **통제 검토 기준까지 몇 분 남았는지**를 보여주고,
> 그 판단 규칙이 맞는지는 **과거 사건(오송 2023)으로 검증**한다.

## 2. 무엇이 바뀌었나

```
  [이전]  사건 재생 뷰어                       [지금]  지하차도 통제 판단 트윈
  ───────────────────────────                ───────────────────────────────
  주인공 : 과거 사건 4개                       주인공 : 지하차도 1곳 (궁평2지하차도)
  시간   : 이미 끝난 과거                      시간   : 지금 (실시간 수위)
  질문   : "그때 막았다면?"                    질문   : "지금 막아야 하나?"
  사례   : 오송·서울·포항·안동 각각 관제 화면     사례   : 오송 = 규칙 검증용, 나머지 = 비교 1장
  쓰는 때 : 사고 뒤 돌아볼 때                   쓰는 때 : 장마철 당직 중
```

**바뀌지 않은 것**: 과거 사건 재생과 "통제 시각을 바꿔보기(반사실)"는 그대로 있다. 다만 주 화면이 아니라
**"이 규칙을 믿어도 되나"를 확인하는 검증 도구**로 역할이 바뀌었다.

### 왜 바꿨나

- 이전 제품은 "과거 사례를 재구성해서 보여주는 것"이라 **디지털 트윈이라 부르기 어렵고 쓸 곳이 안 보였다**.
- 제출 기획서의 정체성은 처음부터 **"홍수 대응 의사결정 디지털 트윈 · 사용자 = 지자체 재난·도로 담당자 · 핵심 = 지하차도 통제 시각"** 이었다. 사례 수를 늘리는 쪽으로 가면서 여기서 멀어졌다.
- 트윈은 **현실의 대상 하나(시설)** 와 짝을 이뤄야 한다. 사건은 끝나지만 지하차도는 매년 장마를 맞는다.
- 훈련 시뮬레이터 방향은 가지 않는다.

## 3. 누가, 언제 쓰나

**사용자**: 지자체 재난안전과 · 도로관리사업소 당직자 (예: 충청북도도로관리사업소)

```
 장마철 새벽 04:40, 비가 계속 온다 (2023-07-15 실제 수위)
        │
        ▼
 ① 보드를 연다 ─────────▶ 궁평2지하차도 · 연결 관측소 미호강교 수위 8.04 m
        │                   단계: 경보 · 계획홍수위(9.38 m)까지 1.34 m
        ▼
 ② 권고를 본다 ─────────▶ «감시» → 상승 속도가 빨라지면 «통제 검토»로 바뀜
        │                   "계획홍수위까지 현재 속도로 N분"
        ▼
 ③ 판단은 사람이 ───────▶ 현장 확인 · 진입 차단 여부는 담당자가 결정
                            (트윈은 근거와 남은 시간을 보여줄 뿐 자동 차단하지 않는다)
```

행정안전부는 오송 이후 지하차도 통제 기준을 **침수심 15 cm → 5 cm**로 낮췄다(2026-05 보도, 원문 확보 필요).
FloodOps는 침수심을 재지 않는다. 대신 **물이 들어오기 전에 움직이는 선행 지표(하천 수위)** 로
"기준 도달 전 몇 분이 남았나"를 미리 보여주는 **보조 판단 도구**다.

## 5. 판단 규칙 (`river_stage_v1`)

미호강교 수위 기준선 (궁평2지하차도에 연결):

```
 수위(m)  0 ──────── 5.0 ──────── 7.0 ──── 8.0 ────── 9.38 ─────▶
           정상       관심        주의보    경보     계획홍수위
                                           │◀─ 60분 ─▶│
                                           └ 이 구간에서 현재 속도로 60분 안에
                                             계획홍수위에 닿으면 → «통제 검토»
                                                      │
                                                      └ 닿으면 무조건 «통제 검토»
```

**«통제 검토»가 뜨는 조건** = ① 계획홍수위 도달, 또는 ② 경보 수위 이상 + 현재 속도로 60분 안에 계획홍수위 도달

계획홍수위를 기준점으로 쓴 이유: 국무조정실 감찰이 **06:40 계획홍수위 도달을 "통제 요건 충족 시각"** 으로 봤다.

## 6. 오송 2023으로 검증한 결과

### 같은 규칙을 그날 수위에 적용하면

```
 04:10 홍수경보      05:50 ◀ 트윈 첫 «통제 검토»    06:50 계획홍수위   08:09 제방 붕괴   08:27 지하차도 유입
 ──●──────────────────────●───────────────────────────●─────────────────●───────────────●──▶
                          │◀────────────────── 157분 ──────────────────────────────────▶│
                          │◀──────────────── 139분 ─────────────────────▶│
```

실제로는 통제가 없었다. 트윈 규칙이면 **유입 157분 전**에 통제 검토를 권고했다.

**157분을 읽는 법 (한계)**

| 항목 | 상태 |
| --- | --- |
| 자료 | 2023년 당시 실시간 화면이 아니라 **2026-10에 홍수통제소에서 다시 받은 보관 10분 수위**로 계산했다. 실시간 10분 값이 늦게 채워지거나 빈 사례가 있어(2026-10 비홍수기 확인), 그날 05:50에 같은 값이 실시간으로 보였는지는 확인하지 않았다 |
| 기준값 | 경보 8.0 m·계획홍수위 9.38 m는 **2026년 조회한 관측소 현재 값**이다. 2023년 당시 값과 같은지는 확인하지 않았다(홍수통제소 문의 예정) |
| 계획홍수위 도달 시각 | 국무조정실 발표는 06:40, 보관 자료로는 06:50이다(10분 차이, DQ-009) |
| 센서 오류 | 2023-05-16 계단 오류 67개 값을 연구 격리로 뺀 결과다. 빼지 않으면 그날 가짜 권고가 11시간 생긴다(157분이 아니라 "다른 해 0건"에 영향) |
| 미래 값 사용 | 없다. 규칙은 각 시각에 그 시각과 **직전 30분 수위만** 본다(`twin._review_flags`) |

→ 157분은 "보관 자료와 현재 기준값으로 같은 규칙을 다시 돌린 결과"이고, 그날 실제 운영에서 157분을 확보했을 것이라는 주장이 아니다.

### 기준을 당기면? (통제 기준 검토 탭)

| 권고 기준 | 2023 첫 권고 | 유입까지 | 다른 해(2019~2026) 권고 |
| --- | --- | --- | --- |
| 계획홍수위 도달만 | 06:50 | 97분 | 0건 |
| **경보 + 60분 (현재 규칙)** | **05:50** | **157분** | **0건** |
| 경보 + 120분 | 04:40 | 227분 | 1건 (2025-07-17, 40분) |

→ 기준을 앞당기면 일찍 알리지만, 다른 해에도 권고가 생긴다. **이 맞바꿈을 담당자가 보고 고르게 하는 것**이 핵심이다.
2025-07-17 구간은 실제 침수·통제 기록을 아직 확인하지 않아 "오경보"로 단정하지 않는다.

- 사용 자료: 미호강교 2019~2026 연중 10분 수위 409,152칸 (빠진 칸 0)
- 품질: 2023-05-16 센서 계단 오류(67개 값)는 규칙에서 뺀다. 빼지 않으면 가짜 "계획홍수위 도달" 11시간이 생긴다.

## 7. 하지 않는 것 (정직하게)

| 하지 않는 것 | 이유 |
| --- | --- |
| 침수심 측정 | 센서가 없다. 수위는 선행 지표일 뿐이다 |
| 자동 차단 | 결정은 담당자·현장 기준이 우선이다 |
| 공식 침수범위 | 지도 위 범위는 HAND 근사이며 공식 침수범위·수심이 아니다 |
| 6시간 수위 예측으로 권고 | 예측 모델(전국 224개 관측소 학습)은 **연구 카드**로만 보여주고 권고에 쓰지 않는다. 오송 새벽 실제 상승이 예측 상한도 넘었다 |
| 사망자·피해액 감소 추정 | 근거가 되는 검증 모델이 없다 |

## 8. 확장 — 다른 지하차도로 넓히는 방법

```
  시설 등록 형식 (같은 틀)
  ┌───────────┬──────────────┬───────────────┬──────────────┐
  │ 시설 정보  │  연결 관측소   │  판단 규칙      │  검증 사건    │
  │ 이름·위치  │ 수위/강우     │ 단계·임계·리드  │ 과거 침수 기록 │
  │ 관리기관   │ 대표성 확인    │ (시설별로 따로) │ 으로 백테스트  │
  └───────────┴──────────────┴───────────────┴──────────────┘
```

- **후보 목록은 확보했다**: 공공데이터포털 공식 CSV 4종, 출처 행 1,053개 (국토부 938 · 인천 42 · 부산 59 · 부천 14), 충북 후보 32곳.
  OSM으로 282곳에 좌표, 5 km 안 수위 관측소 228곳 연결.
- **운영 등록은 아직 0곳 (궁평2만 등록)**. 목록 확보와 운영 등록을 구분한다.
- 등록 조건: 실제 유입 경로 · 대표 관측소 확인 · 현장 계측 · 그 시설의 과거 사건으로 백테스트.
  **오송의 임계 수치를 다른 시설에 복사하지 않는다.** 가까운 관측소라고 대표성이 보장되지 않는다.
- 시설 유형 두 가지: ① 하천 영향형 (오송처럼 강물이 넘침, 구현됨) ② 내수 배수형 (도시 빗물이 고임, 정의만).

### 다른 사례(서울·포항·안동)는?

별도 관제 화면이 아니라 **"검증 사례" 1장** (`GET /api/cases/lead-times`)으로 내린다.
각 사례에서 실제 대응 시각과 가정한 대응 시각의 선행 시간 차이만 보여준다. 사례 간 순위 비교는 하지 않는다.

| 사례 | 실제 대응 | 가정한 대응 |
| --- | --- | --- |
| 2023 오송 | 통제 없음 | 06:40 통제 → 유입 107분 전 |
| 2022 서울 | 21:19 문자 (−20분) | 20:49 경보 → +10분 |
| 2022 포항 | 06:30 안내 (+7분) | 06:00 안내 → +37분 |
| 2026 안동·의성 | 00:00 대피 (+30분) | 23:40 대피 → +50분 |
