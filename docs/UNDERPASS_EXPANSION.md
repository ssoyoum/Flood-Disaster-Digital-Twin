# 지하차도 확장 자료 조사

조사·원본 확보: 2026-10-10 KST. 확장성의 근거는 시설 목록 확보와 시설별 관측·판단 검증을 함께 보여주는 것이다. 현재 확보한 목록은 후보 탐색 자료이며 운영 시설 등록이 아니다.

## 확보한 공식 자료

아래 네 자료는 CSV 원본을 실제 다운로드하고 헤더·행 수를 확인했다. 원본은 `data/raw/facilities/`에 보존하고, 해시·인코딩·기준일·포털 수정일은 [출처 manifest](../data/manifests/underpass-catalog.json)에 기록했다.

|---|---|---:|---|---|

총 **1,053개 출처 행**이다. 전국 자료와 지역 자료의 중복을 합치지 않았으므로 고유 시설 수가 아니다. 전국 자료도 시설물안전법 적용 대상만 포함하므로 전국 지하차도 전체 수·시장 규모로 사용하지 않는다. 종별·구조 안전등급을 침수 위험등급으로 변환하지 않는다. 자료명 기준일과 포털 수정일도 별도로 읽는다.

추가로 [서울시설공단 지하차도 관리 페이지](https://www.sisul.or.kr/open_content/driveway/business/tunnel.jsp)에서 배수펌프·침수감지·집수정 수위계·CCTV·차단시설의 **합계** 공개를 확인했다. 개별 시설별 센서 시계열/API 개방은 확인하지 못했다. 이 페이지의 29개소와 [도로인프라 자산관리 페이지](https://www.sisul.or.kr/open_content/driveway/business/asset.jsp)의 30개소가 달라 최신 관리대장의 기준일·범위 확인이 필요하다.

## 저장한 목록과 재현

- [전체 출처별 목록](../data/processed/facilities/underpass_inventory.csv): 1,053행. 원래 제원과 전체 원본 컬럼을 `source_attributes_json`에 보존한다.
- [충북 후보 목록](../data/processed/facilities/chungbuk_underpass_candidates.csv): 전국 자료의 충청북도 32행. 궁평2지하차도도 포함한다.
- 상태는 모두 `CATALOG_ONLY`, 구동 유형은 `unverified`다. 좌표·관측소는 공란이며 자료가 없는 값을 만들지 않는다. 같은 이름의 오창지하차도도 출처 행을 보존했다.
- `source_record_id`는 데이터셋 ID와 CSV 행 번호로 만든 출처 식별자다. 전국 공통 시설 ID 또는 갱신 후 영구 식별자를 뜻하지 않는다.

```powershell
# 원본을 다시 받고 목록·manifest 생성 (공개 CSV, API 키 불필요)
python data/scripts/collect_underpass_catalog.py --download
# 로컬 원본으로 재생성 (네트워크 없음)
python data/scripts/collect_underpass_catalog.py
```

이 목록은 운영 레지스트리 `FACILITIES`와 분리한다. 주소를 지도 좌표로 변환하더라도 좌표 검증 전에는 상태 판단을 활성화하지 않는다.

## 교류회에서 얻을 도움과 발표 근거

자료 협력 요청의 초점은 관리대장(좌표·관리기관), 시설별 펌프/센서·배수계통, 시각이 있는 과거 통제 기록, 담당자의 현재 업무 흐름이다. 자료 제공 가능 기관과 실증 후보를 찾되 센서 설치 여부와 공개 API 제공 여부를 구분해 기록한다.

발표에는 "공식 출처 4종·1,053행 확보 → 충북 후보 32행 → 위치/관측/규칙 검증 → 시설별 등록 → 과거 사건 대조 → 현장 실증"을 제시할 수 있다. 현재 확인한 성과는 목록 확보와 후보 탐색까지다. 전국 운영 가능·938곳 도입 가능·구매 의향 확보를 주장할 근거는 아직 없다.

## 공공 API로 확보한 자료 (2026-10-26)

### 전국 지하차도 좌표 — 국토교통부 도로 교량 및 터널 현황정보

```powershell
python data/scripts/link_facilities_to_gauges.py tunnels --hyear 2024   # API → road_tunnels.csv (DATA_GO_KR_SERVICE_KEY)
python data/scripts/match_underpasses_api.py                            # 국토부 938행과 대조 → underpass_api_coordinates.csv
python data/scripts/link_facilities_to_gauges.py link --csv data/processed/facilities/underpass_api_coordinates.csv \
    --name-col name --lat-col best_latitude --lon-col best_longitude --id-prefix underpass_coordinates --sido-col sido --sgg-col sgg
python data/scripts/build_facility_candidates.py
```

- `getTunlList` 2024년 자료: 터널 3,924행, 그중 지하차도 927행(시작점 좌표 유효 897행). 시작·끝점 좌표, 관리기관, 연장, 준공년도가 있다.
- 국토부 시설물안전법 목록 938곳과 이름·시도·시군구로 대조한 결과(`data/manifests/underpass-api-coordinates.json`):

| 항목 | 곳 |
|---|---:|
| API 좌표 확보 | 722 |
| 기존 OSM 좌표 | 424 |
| 최종 좌표(API 722 + API 없는 곳의 OSM 31) | 753 |
| API로 새로 좌표가 생김 | 333 |
| API 좌표가 0 등 무효 | 22 |
| API에 같은 이름 없음 | 194 |
| 목록에 없는 API 지하차도 | 175 |

- OSM·API 좌표가 둘 다 있는 389곳의 거리 차이는 중앙값 17 m, 90% 207 m. 1 km 넘게 차이 나는 22곳을 확인해 보니 **틀린 쪽은 OSM**이었다. 같은 이름의 다른 도시 시설을 잡은 경우다(거제 옥산 → 경산, 창원 성주 → 경북 성주군, 평택 중앙 → 서울 중구, 의정부 용현 → 인천 용현동).
- 대조 규칙:
  - 이름 + 시도 + 시군구 첫 단어가 같으면 매칭한다.
  - 시군구가 다르면 이름이 **목록과 API 양쪽에서 도 안에 하나뿐일 때만** 받는다. 세종(시군구 없음)과 구 경계 시설(양재 서초/강남, 모래내 마포/서대문 등) 17곳이 해당하고, `api_sgg_differs=true`로 표시한다. 처음에는 한쪽만 확인해서 용인·수원·평택의 신대지하차도 3곳이 모두 수원 좌표를 받았다.
  - 2023 목록의 "전라북도"는 2024 API의 "전북특별자치도"와 같게 본다. 이걸 빼먹어 전북 20곳이 하나도 매칭되지 않았고, 고친 뒤 15곳이 매칭됐다.
- `best_*` 좌표는 API를 우선하고 API가 없을 때만 OSM을 쓴다. OSM 점은 두 경우에 버린다(`osm_dropped`, 4곳).
  - 다른 시군구의 같은 이름 API 시설과 1 km 안이고, 목록상 시군구의 API 시설들과 10 km 넘게 떨어진 경우: 평택 신대(→ 수원), 서초 내곡(→ 고양). 가까운 5곳(위례 하남/송파, 매헌 과천/서초, 담터 구리/노원, 의왕 복합물류, 용인 신대)은 경계 구조물로 보고 `osm_is_other_facility`만 남긴다.
  - 목록상 시군구의 홍수통제소 관측소 어디서든 25 km 넘게 떨어진 경우(`osm_city_station_km`): 영동 계룡지하차도(복) 916(대전 유성, 35 km), 안산 중앙지하차도 170(서울 중구, 26 km — 평택 중앙의 잘못된 OSM 점과 같은 점). API 좌표 570곳은 99%가 같은 시군 관측소에서 14.9 km 안이라 25 km를 기준으로 했다.
  - 이 검사를 넣게 된 계기: 시도 열을 연결 파일에 넣자 916이 "충북" 시설로 집계되면서 대전 강우를 받아, 오송 사례의 "충북 시설 중 첫 주의 이상"이 12:00 계룡지하차도(복)로 바뀌었다. 예전에는 지역을 가까운 관측소로 정해 대전으로 분류돼 드러나지 않았다.
- 한 API 행을 목록 두 줄이 나눠 가진 경우는 35곳이다(`api_shared_with`). 대부분 상·하행처럼 한 시설을 두 줄로 적은 것이다. 청주 오창지하차도 520·937은 같은 점을 받았다.
- 핵심 시설 좌표 차이: 궁평2 9 m, 만년 90 m, 오량 89 m, 진터 40 m. 초량 제1·제2는 API로 처음 좌표가 생겼다. 안양 평촌지하차도는 API에만 있고 국토부 목록에는 없다.

#### 감시 보드 관측소 연결과 후보 갱신

`facility_gauge_links.csv`를 위 좌표로 다시 만들었다. 시설 ID(`underpass_coordinates:{국토부 순번}`)는 그대로 두어 사건 검증·후보가 쓰는 ID가 바뀌지 않는다. 시도·시군구도 함께 넣어, 감시 보드가 가까운 관측소 대신 목록상 시도로 지역을 정한다.

| 항목 | 이전 (OSM, 2026-10-19) | 이후 |
|---|---:|---:|
| 연결 대상 시설(운영 1 포함) | 425 | 754 |
| 5 km 안 수위 관측소 | 348 | 638 |
| 5 km 안 홍수예보 지점 | 66 | 159 |

- 기존 시설 중 가장 가까운 관측소가 바뀐 곳은 17곳이다. 15곳은 OSM 오매칭이 바로잡힌 것이다(거제 옥산 대구 성동교 → 거제 독봉교, 의정부 용현 인천 연수교 → 의정부 신곡교, 창원 성주 경북 성주군 성산교 → 창원 퇴촌3호교 등). 서울 성산(영등포)은 OSM 점이 마포 성산과 같은 점이었고, 군자는 3.57 km → 3.54 km로 근소하게 바뀌었다.
- 좌표를 버린 4곳(평택 신대·서초 내곡·영동 계룡(복)·안산 중앙)은 연결에서 빠졌다.
- 사건 검증 시설의 관측소는 그대로다: 궁평2 미호강교 1.17 km, 만년 만년교 0.22 km, 진터 만년교 0.92 km, 오량 1.15 → 1.08 km. 초량 제1은 처음 연결됐다(3.75 km).
- `data/facilities/candidates.json` 후보는 7곳 → 12곳. 좌표가 없던 오송바이오폴리스(519)·학평(523)에 좌표가 생겼고, 오창(520·937)·가화(923)·묵방(935)·달천(938)이 새로 조건(충북 · 5 km 안 홍수예보 지점)을 넘었다. 기존 후보는 좌표만 수 m 움직였고 관문 판정은 같다. 계룡(복) 916은 좌표가 없어져 제외 목록(`excluded`)에서도 빠졌다.
- 사건 검증 성적표(`case_scorecard.json`)를 다시 만들었다. 오송·대전 4건 모두 대상 시설의 단계는 모든 시각에서 같다. 지역 집계만 바뀌었다(오송 시점 충북 16 → 26곳, 대전 28 → 34곳). 오송의 "충북 시설 중 첫 주의 이상"은 무심천 하상도로 15:00 → 옥천 가화지하도 14:00(12시간 강우 113 mm ≥ 호우주의보 기준량 110 mm)이다. 가화지하도는 API로 좌표가 생긴 옥천 시설이다.
- 다요인 데이터셋의 `facility-profiles.csv`도 425 → 754행으로 다시 만들었고 감사(`audit_multifactor_dataset.py`)는 통과한다.

### 사건 강우 — 기상청 API 허브 AWS 매분자료

```powershell
python data/scripts/collect_kma_aws_event.py --event busan-choryang-2020-07-23 --lat 35.119110 --lon 129.044801 --start 2020-07-23T18:00 --end 2020-07-24T00:00
```

`nph-aws2_min`에 과거 시각을 주면 그 분의 전국 AWS 누적 강우가 나온다. 초량 제1지하차도 반경 5 km의 4개 관측소를 10분 간격으로 받았다(`data/processed/kma/events/busan-choryang-2020-07-23_aws.csv`).

| 관측소 | 거리 | 표본 중 최대 1시간 강우 | 표본 중 최대 15분 강우 |
|---|---:|---|---|
| 부산(159) | 1.98 km | 81.3 mm (21:40) | 30.7 mm (21:30) |
| 부산남구(942) | 3.97 km | 75.0 mm (21:40) | 25.5 mm (21:40) |
| 부산(레)(160) | 4.08 km | 60.0 mm (21:30) | 24.0 mm (23:10) |
| 부산진(938) | 4.99 km | 51.5 mm (21:20) | 19.0 mm (21:20) |

10분 간격 표본의 최댓값이라 실제 연속 최댓값보다 작을 수 있다. 부산진은 21:30 이후 16개 시점이 비어 있고 채우지 않았다. 21:00까지 부산(159)의 1시간 강우는 24.1 mm였다.

### 호우특보 과거 이력 — 기상청 API 허브 특보현황

```powershell
python data/scripts/collect_kma_warning_event.py --event busan-choryang-2020-07-23 --area 부산광역시 --start 2020-07-23T06:00 --end 2020-07-24T03:00
python data/scripts/collect_kma_warning_event.py --event osong-2023 --area 청주시 --start 2023-07-14T00:00 --end 2023-07-15T09:00
```

발표 이력 API(`wrn_met_data.php`)는 이 키로 승인되지 않았지만, 특보현황 `wrn_now_data.php`에 과거 시각(`tm`)을 주면 그 분 기준 구역별 최신 특보가 나온다. 10분 간격으로 받아 바뀐 지점을 남겼다(`data/manifests/kma-warning-events/`). 실패 0건(3회 재시도).

| 구역 | 변화 (발표 시각 → 발효 시각) |
|---|---|
| 부산광역시 2020-07-23 | 13:00 호우주의보 발표 → 14:00 발효 · **20:00 호우경보 변경** · 07-24 00:20~00:30 사이 해제 |
| 청주시 2023-07-14~15 | 07-13 22:00 호우주의보 · 07-14 04:00 호우경보 발표 → 05:00 발효 · 06:30 주의보로 변경 · **12:10 호우경보 변경**, 07-15 09:00까지 유지 |

- 응답은 구역별 **최신 명령 1건**만 준다. 발효 시각이 뒤인 명령이 오면 그때까지 유효하던 특보는 보이지 않으므로 `in_effect=false`로 남기고 그 사이 수준을 추정하지 않는다.
- 두 표본 사이에 시작하고 끝난 변화는 놓칠 수 있다. 보이는 변화는 기상청 발표 시각(TM_FC)을 그대로 쓴다.
- 오송: 홍수경보(07-15 04:10)와 계획홍수위 도달(06:40) 시점에 청주시는 호우경보 중이었다. 지침 2.1.7(8)④(호우특보 중 급격한 수위 증가)를 과거 사건에 판정할 수 있는 입력이다.
- 초량: 호우경보(20:00)가 부산(159) 1시간 강우 급증(21:30 74.6 mm, 21:40 81.3 mm)보다 앞선다. 사고 시각은 판결문으로 확인해야 하므로 선행 시간은 아직 계산하지 않는다.
- 같은 수정으로 감시 보드의 현재 호우특보 연결도 동작한다. 기존 파서가 실제 응답 형식(대시가 붙은 헤더, 쉼표 구분, `주의`)을 읽지 못해 매번 `ValueError`로 실패하고 있었다.
