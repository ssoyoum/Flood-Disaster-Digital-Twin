# 6시간 최대 수위 상승 예측 모델 (실명 관측소 재학습)

확인일: 2026-10-10. `water-level-rise` 연구(익명 관측소·합성 시각)의 입력 계약을 **홍수통제소 실명 관측소의 실제 시각 자료**에 그대로 적용해 다시 학습한 모델이다. `#twin` 보드의 "6시간 최대 상승 예측 · 연구 카드"가 이 모델을 쓴다. 통제 권고는 이 예측을 읽지 않는다.

## 무엇을 예측하나

- 목표: `max(WL(t+1h), …, WL(t+6h)) − WL(t)` (m). 앞으로 6시간 안의 최대 상승량이고 음수도 유효하다.
- 예측하지 않는 것: 도달 시각, 시각별 수위 곡선, 지하차도 침수심.
- 카드는 `WL(t) + 예측 상승량`을 관측소 공식 수위(주의보·경보·계획홍수위)와 비교해 "6시간 안 도달 예상"만 표시한다.

## 자료와 입력 계약

| 항목 | 값 |
| --- | --- |
| 수위 | 홍수통제소 홍수예보 지점 223곳 + 미호강 상·하류 = 224곳, 1시간 자료 2019-01-01~2026-10-10 (`docs/HRFCO_HISTORY.md`) |
| 강우 | 수위 관측소마다 가장 가까운 홍수통제소 강우 관측소(값이 없으면 2·3번째 후보), 188곳. 224곳 중 215곳 연결, 중앙값 거리 2.88 km |
| 입력 | 기준 시점·1·3·6·12·24시간 전 수위, 1·6·24시간 누적 강우, 파생 변화량·가속도·24시간 범위, 관측소별 중앙 수위·상승 표준편차·99% 분위 (연구 계약의 `FEATURES` + `make_features`) |
| 빠진 입력 | 연구 계약의 IMERG·레이더·유역 변수 16종은 이 경로에 없어 쓰지 않는다 |
| 행 선택 | 24시간 안에 수위가 0.2 m 이상 움직였거나, 목표가 ±0.2 m 이상이거나, 24시간 강우가 10 mm 이상인 "활동" 시간 전부 + 나머지 평온 시간의 5% 무작위 |
| 품질 | 1시간 사이 3 m 넘게 뛰는 값(미호강교 2023-05-16 같은 센서·기준면 오류)은 앞뒤 값까지 버린다. 지연·누락 시각은 빈 값으로 두고 정시 입력이 하나라도 없으면 행을 만들지 않는다. 그 위에 품질 감사 마스크(`data/processed/hrfco-quality/*_quality.csv`의 `training_window_usable`, 아래 "품질 마스크")를 적용한다 |
| 학습 | LightGBM 회귀(31 leaves, 800 라운드, 학습률 0.03) + 같은 입력·행으로 90% 분위 회귀(`objective=quantile`, `alpha=0.9`)를 따로 학습한다. 관측소 통계는 학습 행에서만 계산 |
| 검증 | 연·월 단위 GroupKFold 4폴드(같은 달의 모든 관측소가 한 폴드) + **2023-07 한 달은 학습에서 완전히 제외**해 오송 사건 검증에 쓴다 |

```powershell
python data/scripts/audit_hrfco_quality.py           # 학습 전에 224곳 품질 마스크 생성(Git 제외 산출물)
python data/scripts/train_rise_model.py              # 224곳, 교차검증 포함 약 10분
python data/scripts/train_rise_model.py --stations 3011665 3011635 3011685 --skip-cv
python data/scripts/train_rise_model.py --no-quality-masks --no-q90   # 마스크·상한 모델 없이 이전 방식 재현
```

산출물: `data/models/rise_lgbm_1h.txt`(중앙 모델 텍스트, 2.4 MB), `rise_lgbm_1h_q90.txt`(상한 모델, 2.5 MB), `rise_station_stats.json`, `rise_model_card.json`(아래 수치 전부), 같은 내용의 `data/manifests/rise-model.json`. 상한 모델 파일이 없으면 API는 상한 필드를 `null`로 두고 중앙 예측만 낸다.

## 품질 마스크

`audit_hrfco_quality.py`가 224곳 전부에 만든 시간별 마스크에서, 기준 시점·과거 입력 6시점·미래 정답 6시점이 전부 유효한 행(`training_window_usable`)만 학습에 쓴다. 기존 3 m 급변 제거는 그대로 둔다.

같은 224곳 1시간 자료에서 학습 가능 창(표본 추출 전)을 세 방식으로 세어 대조했다(2026-10-12).

| 방식 | 학습 가능 창 | 기존 대비 |
| --- | ---: | ---: |
| 급변 제거만(이전 학습) | 14,667,115 | — |
| 급변 제거 + 품질 마스크(현재 학습) | 14,667,103 | −12 |
| 품질 마스크만(급변은 검토 표시만) | 14,667,648 | +533 |

- 마스크가 더 빼는 12개 창은 전부 미호강교 2023-05-16 연구 격리 구간이다. 누락·비유한 값은 원래도 정시 입력 조건에서 빠지고 있었다.
- 반대로 급변 규칙은 20곳의 계단 40개 주변에서 마스크가 허용하는 창 545개를 더 버린다(가장 많은 곳 3004685 77개, 3013605 65개). 품질 정책은 급변을 "검토 표시"로만 두므로, 이 계단들을 원출처로 확인하기 전까지는 두 규칙을 함께 적용해 보수적으로 뺀다.
- 미호강교만 보면 마스크만 적용 시 67,967개로 감사 요약(`hrfco-quality.json`의 `usable_training_windows`)과 같다.

보드 재생(`FLOODOPS_TWIN_MODE=replay`, 10분 수위 + 청주금천 AWS 강우)에서는 강우 관측망이 달라 수치가 조금 다르다. 04:10에 수위 7.69 m, 중앙 +1.76 m → 9.45 m(계획홍수위 도달 예상), 상한 +2.83 m → 10.52 m다. 04:00은 중앙 9.37 m로 계획홍수위에 0.01 m 못 미치고 상한은 03:00부터 10.0 m 안팎을 낸다. 같은 시각 권고는 규칙대로 "감시"이고, 규칙(`river_stage_v1`)의 첫 «통제 검토»는 05:50이다. 이전 문서의 04:10 "+1.94 m → 9.63 m"는 마스크 적용 전 모델로 다시 돌려도 +1.86 m → 9.55 m라 재현되지 않아 이 값으로 바꿨다.

주의: 전국 자료로 학습한 모델은 미호강교의 급상승을 보수적으로 본다. 미호강 3곳만으로 학습하면 같은 창에서 RMSE 1.01 m, 선행 180분으로 비슷했지만 홀드아웃 전체 성능은 떨어진다.

중요도(gain) 상위: `wl_change_6h`, `station_rise_std`, `wl_acceleration_3h`, `wl_change_1h`, `sfc_rain_1h`, `wl_above_station_median`.

## 보드와 API

- `GET /api/twin/facilities/{id}/rise-forecast?at=` — `backend/app/rise_model.py`. 시설 관측소의 26시간 창에서 정시 입력(`water_level_bridge.water_inputs`)과 강우 합계를 만들고 예측한다. 정시 입력이 하나라도 없거나(`MISSING_EXACT_LAGS`) 관측이 오래되면(`OBSERVATION_NOT_FRESH`) 예측하지 않는다. 모든 응답에 `kind: "RESEARCH"`, `control_decision_usable: false`.
- 실시간 모드의 강우: 기상청 어댑터가 없어 결측으로 들어간다(모델은 결측을 처리한다). 재생 모드는 2023년 청주금천 AWS 시간 강우를 쓴다. 학습 강우는 홍수통제소 강우계이므로 관측망이 다르다.
- 실행 환경: `lightgbm==4.7.0`, 컨테이너는 `libgomp1` 필요, 모델 파일은 `data/models/`로 이미지에 복사한다. 모델 파일이 없으면 카드가 "학습된 모델 파일이 서버에 없습니다"를 보여주고 다른 기능은 영향이 없다.

## 한계와 다음 단계

- 급상승 과소 예측: 1 m 초과 구간 RMSE 0.99 m. 90% 분위 상한을 붙였지만 오송 01:00~03:00처럼 실제 상승이 상한도 넘는 사건이 있고 홀드아웃 포함률이 85.7%다. 사건 가중 학습이나 분위 보정(conformal 등)을 다음에 검토한다.
- 급변 3 m 규칙이 20곳 40개 계단 주변 창 545개를 마스크보다 더 뺀다. 원출처로 계단을 확인한 뒤 급변 규칙을 마스크로 대체할지 정한다.
- 실시간 모드(`HRFCO_API_KEY` 설정)에서는 `at`에 과거 시각을 줘도 강우가 기상청 어댑터(미연결)로 들어가 결측이 된다. 과거 시각 비교는 `FLOODOPS_TWIN_MODE=replay`로 한다.
- 강우는 가장 가까운 지점 1곳의 합계다. 유역 평균 강우·레이더가 들어오면 연구 계약의 나머지 입력을 채울 수 있다.
- 학습에 없는 관측소는 관측소 통계가 결측으로 들어가므로 새 시설을 등록할 때는 그 관측소를 학습 목록에 넣고 다시 학습한다.
- 관측소 기준면이 서로 달라도 `wl_above_station_median`으로 보정하지만, 기준면 변경 이력이 있는 관측소는 따로 확인해야 한다.
