# FloodOps 시장성·유용성 검증 실행안

작성일: 2026-10-09. 상태: **인터뷰·파일럿 준비 완료, 실증 결과 미확보**.

이번 검증의 질문은 “기능이 좋아 보이는가?”가 아니라 “누가 어떤 반복 업무에서 쓰고, 무엇을 대체하며, 어떤 조건으로 도입을 검토하는가?”다. 기존 발표 V2의 시장 가설을 실행 가능한 과제와 기록 양식으로 연결했다. 아래 모집 인원과 판정 기준은 계획이며 실제 성과가 아니다.

## 1. 먼저 검토할 사용 장면

| 후보 | 실제 사용자 가설 | 반복 업무 가설 | 도입 검토자에게 확인할 것 |
|---|---|---|---|
| 지자체 재난·도로 담당 부서 | 재난 담당자, 지하차도·도로 관리자 | 우기 전 훈련, 과거 사건 복기, 통제 시점 검토 | 업무 책임자, 예산 소관, 정보화·보안 검토 주체, 다음 검토 시점 |
| 도로·시설 관리 조직 | 시설 운영자, 안전 담당자 | 시설별 진입 통제 교육, 사고 사례 검토 | 기존 관제·교육 도구와의 중복, 필요한 시설 자료, 운영 책임 |
| 교육·연구 조직 | 교육 담당자, 재난·공간정보 연구자 | 사례 기반 교육, 사건 비교 과제 | 교육 과정 편입 가능성, 학습 평가, 자료 갱신 부담 |

첫 인터뷰는 지자체 재난·도로 업무를 우선한다. 다른 후보는 수요를 비교하기 위한 가설이다. 현재 서비스가 제공하는 과거 사건 재생·대응 시간 비교를 사용 장면으로 삼고, 실시간 자동 통제나 검증되지 않은 피해 감소량을 도입 근거로 제시하지 않는다.

## 2. 교류회 3분에서 얻을 것

1. **Agent 연결 검토:** 직접 분석 API는 정상인데 자연어 질문·후속 대화·모델 응답에서 실패한 경험이 있는 개발자에게 질문 유형, 시간 예산, 도구 입력 계약을 검토받는다. `AGENT_VALIDATION.md`의 재현 표와 `diagnostics` 예시를 보여 준다.
2. **시장 가설 반박:** 재난·도로 실무자에게 가장 최근의 훈련·사건 검토 업무와 현재 도구를 묻는다. FloodOps가 반복적으로 필요한지, 기존 GIS·문서·훈련 체계와 얼마나 중복되는지 확인한다.
3. **파일럿 연결:** 공개 사건 자료로 아래 과제를 수행할 수 있는 실무자 또는 교육 담당자에게 후속 인터뷰·실험 참여 가능성을 묻는다. 참여 의사를 사용자 수·구매 의향으로 합산하지 않는다.

후속 기록: `market-validation/interviews.csv`. 이 파일에는 헤더만 있으며 인터뷰가 완료된 행만 추가한다. 실명·연락처·원문 녹취는 공개 저장소에 넣지 않고 `docs/local/` 등 비공개 위치에서 별도로 관리한다. 상대에게 자동 메시지를 발송하는 기능은 없다.

## 3. 실무 인터뷰 20분 진행표

| 시간 | 질문 | 확보할 근거 |
|---|---|---|
| 0~5분 | 최근 수행한 홍수 대응 검토나 훈련을 순서대로 설명해 주세요. 누가 어떤 자료와 도구를 썼나요? | 실제 업무 1건, 역할, 자료 종류, 소요 시간·빈도의 응답 근거 |
| 5~10분 | 자료 대조·통제 시점 검토·결과 설명 중 어디에서 반복 작업이 생겼나요? 현재 어떻게 해결하나요? | 현재 대안, 어려움, 대체 가능 업무 |
| 10~15분 | 오송 사건에서 08:20 통제 조건과 유입 시각을 비교해 주세요. 무엇을 판단할 수 있고 무엇은 계산되지 않나요? | 관찰한 과제 수행, 기능 이해, 오해·중단 원인 |
| 15~20분 | 이 결과를 다시 쓸 구체적인 업무가 있나요? 기관에서 시범 사용을 검토하려면 누구에게 어떤 자료가 필요할까요? | 반복 사용 장면, 도입 조건, 검토 주체, 다음 행동 |

유도 질문을 줄인다. “유용하죠?”, “도입할 의향이 있죠?” 대신 실제 업무와 다음 행동을 묻는다. 사용자의 칭찬, 소개 가능성, 파일럿 참여, 예산 검토, 계약을 서로 다른 근거로 기록한다. 가격은 먼저 제안해 답을 유도하지 말고 현재 지출·대체 비용·예산 단위와 그 근거부터 확인한다.

## 4. 5~8명 파일럿 계획

동일 참여자가 기존 방식 A와 FloodOps B로 수행한다. 절반은 A→B, 나머지는 B→A 순서로 배정하고 비슷한 난이도의 서로 다른 시간 조건을 사용한다. 예를 들어 조건 세트 1은 08:10·08:20, 세트 2는 08:15·08:25이며 조건 세트와 순서도 교차 배정한다. 대조 방식에도 같은 자료 스냅샷·출처·시각 조건을 제공한다.

| 과제 | 완료 조건 | 채점 시 주의 |
|---|---|---|
| 사건·자료 확인 | 오송 사건과 출처 확인 전 재구성 시각이라는 상태를 찾는다 | 보도·재구성을 공식 확정 관측이라고 말하면 오류 |
| 통제 시점 비교 | 두 통제 조건의 유입 전 여유 시간을 계산·설명한다 | `08:20 → 유입 08:27까지 7분`은 현재 데이터 기준 산술. 인명·피해 감소로 확대하면 오류 |
| 근거·가정 설명 | 출처, 명시한 통제 조건, 계산되지 않은 효과를 함께 설명한다 | HAND 셀 변화와 물리 침수 변화 구분 |
| Agent 후속 질문 | 명시적 조건 질문 뒤 후속 질문을 하고 결과·도구 값을 직접 분석 결과와 대조한다 | 모델 연결 실패와 분석 자체의 실패를 별도 기록 |

진행자는 시작·종료 시각, 도움 횟수, 완료 여부, 실제 답변, 실패 원인을 기록한다. 공통 시간 제한은 실행 전 정하고 미완료를 성공 시간에 포함하지 않는다. 두 방식에 같은 제한을 적용한다. 관찰 후 만족도 1~5점, 다시 사용할 업무, 도입에 필요한 조건을 묻는다.

기록: `market-validation/pilot-results.csv`. 개인정보 대신 익명 participant_id를 쓰고, 과제별·방식별로 한 행씩 기록한다. 시간 단위는 초, 미측정 숫자는 빈칸, pass/fail은 수행을 확인한 뒤 입력한다. 단계 오류가 있으면 원본 증빙은 비공개 경로에 보관하고 식별자를 남긴다.

## 5. 평가와 다음 투자 판단

- 완료율: `완료 과제 수 / 실제 시도 과제 수`. 모집 목표 5~8명을 분모로 삼지 않는다.
- 시간: 참여자별 같은 유형의 A·B 완료 시간을 비교하고 중앙값·범위·미완료 수를 함께 보고한다. 표본이 작으므로 일반화된 효율 개선율로 발표하지 않는다.
- 정확도: 계산·출처·가정 이해를 별도로 집계한다. 물리 효과나 피해 감소의 잘못된 해석은 별도 중대 오류로 기록한다.
- Agent: 요청 수, 모델 설명 완료 수, 도구 결과 폴백 수, 실패 수를 분리한다. HTTP 200이나 `ANSWERED`만으로 모델 설명 성공을 계산하지 않는다.
- 시장 근거: 인터뷰 완료, 반복 업무 확인, 파일럿 후속 일정 확정, 예산 검토 주체 확인을 각각 별도로 센다. 같은 기관의 참여자를 여러 구매 기관으로 세지 않는다.

**다음 개발로 진행할 잠정 기준:** 서로 다른 두 조직 이상에서 구체적인 반복 업무가 확인되고, 파일럿에서 치명적 해석 오류를 해결했으며, 적어도 한 조직과 도입 검토 주체·다음 단계가 확인된다. 이는 내부 의사결정 기준이며 시장 검증 완료나 매출 실적 기준이 아니다. 충족하지 못하면 새로운 사건 확장보다 사용 장면·설명·자료 품질을 먼저 수정한다.

## 6. 가격·운영 검토 표

| 변수 | 근거를 얻을 곳 | 기록 상태 |
|---|---|---|
| 대상 기관 수와 실제 접근 가능한 기관 수 | 범위를 정의한 기관 목록, 확인한 업무 | 미확보 |
| 기관당 구축 범위 | 필요한 사건 수, 시설 자료, 교육 시나리오, 결과물 | 미확보 |
| 연간 운영 비용 | 자료 갱신·모델 호출·서버·지원 인력의 실제 사용량과 견적 | 미확보 |
| 지불 가능 범위·예산 소관 | 구매 검토자 인터뷰와 근거 | 미확보 |
| 수주·갱신 가능성 | 파일럿 이후 실제 검토 단계·계약 | 미확보 |

매출 시나리오를 만들 때는 구축비와 반복 운영비를 분리하고 검증된 입력만 사용한다. 인터뷰 상대의 호감이나 공개 사이트 방문 수를 도입 비율로 대입하지 않는다. 계약·규제·보안 기준은 해당 기관에 확인한 문서와 검토 기록이 생긴 뒤 구체화한다.

## 7. 본선 발표에 넣을 증빙

| 서비스 개발 심사항목 | 현재 준비 | 실제 결과가 생기면 교체할 내용 |
|---|---|---|
| 기획성 15점 | 과거 사건 복기·통제 시점 검토라는 사용 장면 | 실무자 업무와 문제에 대한 인용·근거 |
| 완성도 25점 | API·UI·시간 제한·실패 진단의 자동 검증 | 실제 모델 종단 간 대조 기록, 배포 버전 |
| 확장성 25점 | 사건별 도구 계약과 자료 부족 경계 | 신규 기관·사건 연결에 든 시간과 갱신 절차 |
| 유용성 25점 | 대조 과제·기록 양식 준비 | 실제 참여자 수, 완료·오류·시간·만족도 분포 |
| 발표 10점 | V2 본문·부록과 교류회 3분 자료 | 검증 결과·실패 사례·다음 조치를 같은 장에 제시 |

기존 V1·V2 PPT는 보존한다. 실증 결과를 얻은 뒤 장표를 갱신하며 이번 준비만으로 사용자 수·만족도·도입 실적이 확보됐다고 표현하지 않는다.
