# water-level-rise의 구성으로 FloodOps를 발전시키는 방법

확인일: 2026-10-10. 검토 대상은 옆 프로젝트의 데이터 구성·원출처·특징 설계·검증 절차다. 대회 학습 CSV를 FloodOps의 시설 관측으로 사용하지 않는다.

## 출처를 확인한 결과

옆 프로젝트는 원자료 수집 시스템이 아니라 주최측이 결합한 자료를 학습·검증하는 프로젝트다. 현재 `baseline.py`는 배포 CSV를 읽고, `train_lgbm.py`는 특징 생성·학습·교차검증·저장 모델 추론을 담당한다.

자료 출처는 실제 배포 ZIP의 `data_dictionary.csv`를 기준으로 확인했다. `proposal.md`는 배포 전 초안이라 거기 있는 관측소 수·행 수·분할·단위를 현재 자료의 확정값으로 사용하지 않았다. [KISTI 공식 과제 페이지](https://aida.kisti.re.kr/competition/main/problem/PROB_000000000004603/detail.do)에서도 과제와 배포 ZIP 항목을 확인했다.

| 옆 프로젝트 구성 | 배포 사전의 출처 | FloodOps에서 가능한 발전 | 적용 조건 |
| --- | --- | --- | --- |
| 과거 수위 6종 | WAMIS | 현재 수위뿐 아니라 1·3·6·12·24h 변화와 상승 가속도를 보여주고 예측 입력으로 구성 | 실제 관측소·시각·기준면 유지. 기존 홍수통제소 이력을 활용 |
| 위성·지상 강수 6종 | RAIN-F의 IMERG, AWS/ASOS 격자 | 최근 강우 집중과 선행 누적 강우를 구분하고 수위 반응과 대조 | 홍수통제소 강우계와 원본 격자는 다른 변수. 동일 입력이라고 가정하지 않음 |
| 레이더 요약 3종 | RAIN-F 레이더 | 한 지점 강우계가 놓치는 주변 강우 분포를 보완 | 현재 시각 자료의 제공 경로·지연·집계·단위 추가 확인. 반사도를 강우량으로 임의 환산하지 않음 |
| 유역 특성 7종 | DataON1112 | 관측소별 상류 유역을 연결하고 면적·경사·도시화에 따른 반응 차이를 비교 | 가까운 관측소보다 유역·하천 연결 확인을 우선. 소권역 평균을 지하차도 주변 국소값으로 해석하지 않음 |

RAIN-F DOI는 옆 초안에 [10.22711/0101ND019861063911.0](https://doi.org/10.22711/0101ND019861063911.0)로 기록돼 있다. 이번 웹 확인에서 해당 상세 페이지는 열리지 않아 현재 다운로드·이용조건·실시간 제공 여부까지 확인된 것으로 표시하지 않는다.

[DataON 전국 하천망 및 유역 환경 데이터셋](https://doi.org/10.22711/idr/1112?urlappend=%26file%3D)의 공개 메타데이터에서는 하천 분절·집수지역 GeoPackage, WAMIS 유역 ID, CC BY-NC 표시를 확인했다. 실제 파일의 변수 사전과 이용조건을 확인한 뒤 채택해야 하며, 시장성 검토에 쓰는 상업 서비스 적용 조건도 별도 확인 항목이다.

## FloodOps에서 우선 발전시킬 것

1. **자료 품질과 입력 이력:** 실명 수위의 정확한 시간차 입력, 누락·중복·의심 구간 추적. 모델이 무엇을 보고 예측했는지 확인할 수 있게 한다.
2. **강우와 수위 반응:** 실제 강우계의 1·6·24h 누적·최근 집중 비율과 수위 변화·가속도를 함께 분석한다. 지상 격자 변수의 이름·학습 모델을 그대로 가져오지 않는다.
3. **유역에 따른 시설 연결:** 시설 → 유입 하천/배수구역 → 대표 관측소 → 유역 특성을 등록한다. 하천 인접형과 내수 배수형을 나눠 후자는 현장 침수심·펌프·배수 자료가 필요하다고 표시한다.
4. **검증과 Agent 설명:** 사건별 학습/평가 분리, 단순 지속·선형 외삽과 비교, 급상승 과소예측·임계 도달 누락·오경보를 함께 설명한다. Agent는 실제 도구 결과와 출처를 설명하고 통제 실행이나 검증되지 않은 피해 감소를 주장하지 않는다.

옆 프로젝트의 세 모델 앙상블과 조석 변수는 그 자료에서 검증된 선택이다. 미호강의 운영 조건에서 같은 효과가 있다고 가정하지 않고 먼저 단순 모델과 비교한다. 6시간 최대 상승량의 임계 초과 가능성을 비교할 수는 있지만 정확한 임계 도달 분을 산출하려면 시간대별 예측이 추가로 필요하다.

## 이번 TODO 진행: 관측 품질 감사와 격리 마스크

기존 작업 트리에 실명 관측 재학습과 보드 연구 카드가 추가돼 있어, 이번에는 별도 품질 모듈을 만들었다. 현재 학습·모델 파일·화면을 수정하거나 재학습하지 않았다.

- 정책: `data/manifests/hrfco-quality-policy.json`
- 계산: `backend/app/history_quality.py`
- 실행: `data/scripts/audit_hrfco_quality.py`
- 요약과 원본/정책/산출물 SHA-256: `data/manifests/hrfco-quality.json`
- 시간별 마스크: `data/processed/hrfco-quality/` (로컬 산출물, Git 제외)

```powershell
python data/scripts/audit_hrfco_quality.py --stations 3011665 3011635 3011685
python -m pytest backend/tests/test_history_quality.py -q
```

급변 3 m 이상은 **검토 표시**다. 모든 급변을 센서 오류로 단정해 제거하지 않는다. 반면 시간 누락, 비유한/비숫자 값, 중복 시각은 학습 불가로 표시한다. 수위가 음수라는 이유만으로 제거하지 않는다.

미호강교 2023-05-16 01:00~12:00의 계단 변화를 원출처 확인 전 **연구 학습 격리 구간**으로 등록했다. 센서 오류의 공식 확정은 아니다. 격리된 관측이 기준 시점·과거 입력·미래 정답 중 어느 곳에 쓰이는지 모두 추적한다. 과거 입력 6시점과 미래 정답 6시점이 전부 유효해야 학습 행을 허용하며, 빈 값을 보간하거나 최대값 계산에서 누락된 미래 시간만 생략하지 않는다.

세 자료 모두 `2020-01-01 00:00~22:00`, `2024-01-01 00:00~22:00`의 23시간씩 빠져 있다. 수집 요청·응답을 대조한 보완이 필요하며 보간하지 않는다. 마지막 기록 시각은 2026-12-31이지만 실제 마지막 유효 관측은 2026-10-10 08:00이다. 남은 미래 시간의 빈 행을 수집 완료 관측으로 세지 않는다.

학습 창 수는 **수위만의 품질 조건**을 통과한 개수다. 강우 대표성·레이더·유역·시설 대응성 또는 모델 성능을 검증한 수가 아니다.

## 이어서 할 작업

- 현재 학습과 사상 집계가 이 정책·마스크를 읽게 연결하고, 기존 급변 규칙과 달라지는 행을 대조한 뒤 재학습한다. 지금 요약의 `training_integration_complete`는 `false`다.
- 위 46시간의 수집 공백을 원출처 응답과 확인하고 보완한다. 현재 파일을 임의로 수정하지 않는다.
- 옥산 무자료·부강면사무소/명학리 교체 후보를 품질 메타데이터에 기록했다. 공식 교체 확인 전 두 관측소를 자동으로 이어 붙이지 않는다.
- 검증은 월 그룹뿐 아니라 호우사상 경계와 과거 24h/미래 6h 입력·정답이 평가 구간을 넘는지도 점검한다. 실제 운영 평가는 미래 기간을 남겨 따로 확인한다.
- 유역 연결과 실제 강우 입력을 확인한 뒤 Agent에 관측 근거·입력 누락·예측 한계를 설명하는 도구를 추가한다.
